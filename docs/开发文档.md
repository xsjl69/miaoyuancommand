## 1. 项目概述

- **目标**：做一个 PCR（公主连结）公会战辅助网站，免登录、移动端优先。
- **两大模块**：
  1. **首日排刀**：参考现有静态页 `202609`，展示刀型汇总 + 用户排刀排名。
  2. **轴区**：用户可上传/查看/筛选/排序游戏轴，并对轴进行评论、点赞。
- **技术约束**：前后端均用 Python，数据库用 SQLite。

---

## 2. 技术栈选型（推荐，待确认）

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | **Flask** | 轻量、单文件可起、适合小工具站点；API + 模板渲染都方便 |
| 数据库 | **SQLite** | 零部署、单文件，契合需求 |
| 前端 | **原生 HTML + CSS + 原生 JS**（Jinja2 模板渲染页面，交互用 fetch） | 移动端优先、无构建步骤、易维护 |
| 图片存储 | **本地 `uploads/` 目录 + DB 存路径**，经专用路由安全输出 | 避免 BLOB 臃肿、便于做安全校验与防目录遍历 |
| 部署 | 本地 `flask run` / `waitress` 即可，后续可加 `sites` 发布 | 先跑通再说 |

> 备选：若你更偏好类型化接口与异步，可换 **FastAPI**（不影响 DB/前端结构）。
> 前端也可改为 SPA（Vue/React），但当前需求用原生 JS 足够，避免过度设计。

## 5. 页面与功能设计

### 5.1 整体布局（免登录、移动端优先）
- `base.html`：顶部/底部导航栏，两个入口「首日排刀」「轴区」；若有期数概念，顶部加期数切换下拉。
- `<meta name="viewport" content="width=device-width, initial-scale=1.0">`，CSS 以移动端为基准，表格/卡片在窄屏下可横向滚动或改卡片式。
- 全程免登录；所有写入（上传轴、评论、点赞）均为公开可写（符合需求）。

### 5.2 首日排刀页 `/paidao`
- 复刻参考结构：
  - **刀型汇总**：按 B/C/D 区分组（可折叠 `<details>`），列：刀型编号 / 刀数 / 阵容描述 / 视频链接 / 轴来源 / 轴图（缩略图点击放大）。
  - **用户排刀排名表**：列：排名 / 用户ID / 骑士等级 / 第一刀(上+下) / 第二刀(上+下) / 第三刀(上+下)，加粗项高亮。
  - 交互：用户快速跳转下拉、浮动导航、提示弹窗（复用参考实现）。
- **范围待确认（关键）**：本期默认按「只读展示 + 从 `202609` 数据种子导入」实现。若需要「后台可编辑（增删改刀型/用户/排刀）」请指明（见 §8 Q1）。

### 5.3 轴区列表页 `/axis`
- **查看轴**：卡片/表格展示所有轴，每项显示 **BOSS 编号 / 轴图缩略图 / 伤害**。
- **筛选**：按 BOSS 编号（D1–D5 多选/下拉）、按伤害（区间或阈值）。
- **排序**：按 BOSS 编号、按伤害（升/降）。
- 实现：首次加载拉取全部轴 JSON，前端 JS 做筛选/排序（数据量小，无需反复请求）。
- 点击某项 → 进入轴详情（同页展开或跳转）。

### 5.4 轴详情 + 评论区 `/axis#<id>` 或 `/axis/<id>`
- 顶部展示该轴完整信息：BOSS 编号、轴图大图、伤害（如 `4.5e`）、简介。
- **评论区**（底部）：
  - 已有评论列表：显示文字、图片（缩略图可放大）、上传人、赞数、评论时间。
  - **新增评论**：文字（必填或选填）、图片（选填，走安全校验）、上传人（手动填写，必填）。
  - **点赞**：每条评论可点赞；**可按赞数 / 评论时间筛选排序**评论。

### 5.5 上传轴功能 `/axis`（表单）
- 字段：BOSS 编号（下拉 D1–D5）、轴图（图片，必填，强安全校验）、伤害（数字，单位 e，如 `4.5`）、简介（文字）。
- 提交 → `POST /api/axis` → 存图 + 写 `axis` 表 → 跳转/刷新列表。

| GET | `/uploads/<filename>` | **安全输出**图片（校验存在、设正确 content-type、防遍历） |

## 7. 图片上传安全校验方案（重点）

对所有图片上传（轴图、评论图）统一走 `security.py` 校验，**绝不信任客户端**：

1. **类型白名单**：仅允许 `image/jpeg`、`image/png`、`image/webp`（可按需加 gif）。
2. **魔数校验**：读取文件头字节，验证真实格式：
   - PNG: `89 50 4E 47`
   - JPEG: `FF D8 FF`
   - WEBP: `52 49 46 46 ... 57 45 42 50`
3. **大小限制**：单文件 ≤ 5MB（可配）。
4. **尺寸限制**（可选）：最大宽高（如 4096px），超限拒绝或缩放。
5. **重命名存储**：使用服务端生成的随机名（`uuid4` + 真实扩展名），**丢弃原始文件名**，杜绝路径遍历与特殊字符。
6. **隔离存储**：存于 `uploads/`，不置于可直接执行的目录；通过 `/uploads/<filename>` 专用路由输出，路由先校验文件名仅含安全字符（白名单 `[A-Za-z0-9_-]` 与扩展名）后再读取。
7. **Content-Type 固定**：按真实类型设置响应头，避免浏览器误执行。
8. **失败即拦截**：任一校验不通过返回 400，不落盘。
